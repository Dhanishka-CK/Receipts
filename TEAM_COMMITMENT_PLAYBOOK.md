# Team Commitment & Architecture SLA Playbook
**Version:** 1.0.0  
**Domain:** Engineering Operations, Decision Tracking & Autonomous Conflict Auditing  
**Grounding Authority for Lyzr Multi-Agent System (Receipts)**

---

## 1. Executive Summary & Purpose
This playbook defines the definitive organizational policies, SLA thresholds, and architectural standards used by the **Receipts** autonomous multi-agent system (powered by Lyzr, Qdrant, and Omi).

Every voice statement captured via Omi is audited against this playbook to:
1. Distinguish binding **commitments** and **decisions** from casual conversation.
2. Flag architectural regressions, scope creep, and timeline conflicts.
3. Guarantee that receipts issued to team members are **100% grounded in verified historical memory** with zero hallucination.

---

## 2. Memory Item Classification Taxonomy

| Item Kind | Description | Initial State | Transition Rules |
| :--- | :--- | :--- | :--- |
| **Commitment** | A person explicitly vows to deliver an output, complete a feature, or perform an action by a deadline or implied timeframe. | `OPEN` | • Moves to `BLOCKED` if an active blocker claim links to it.<br>• Moves to `DONE` when completion is verbally confirmed.<br>• Escalates to `OVERDUE` if `deadline_ts < now_ts` without resolution. |
| **Decision** | An agreement or directive defining technical architecture, tools, frameworks, schema design, or workflow standards. | `ACTIVE` | • Moves to `SUPERSEDED` when an authorized new decision explicitly replaces it.<br>• Triggers a high-priority alert if contradicted without prior superseding discussion. |
| **Claim** | A status assertion regarding technical state, blocker, outage, or dependency. | `CURRENT` | • Moves to `RESOLVED` when the unblocking condition or fix is reported. |

## 3. Architectural Decision Policies

### 3.1 Persistence & Database Standards
- **Primary Relational Store:** PostgreSQL is the approved standard for relational data and transactional records.
- **Vector & Semantic Memory:** Qdrant Cloud is the mandatory standard for high-dimensional vector search, fast payload filtering, and agentic working memory.
- **Policy Violation:** Proposing an unvetted alternative database (e.g., MongoDB, SQLite for production, MySQL) without a documented migration proposal constitutes an **Architectural Conflict**.

### 3.2 Authentication & Security SLAs
- Core Authentication APIs and token verification pipelines must have an explicit delivery commitment and owner.
- An authentication component failure automatically blocks all dependent downstream demo flows.

## 4. Conflict & Contradiction Auditing Hierarchy

When the **Auditor Agent** audits a new statement against memories retrieved from Qdrant, it must apply this strict hierarchy:

1. **Direct Contradiction (Confidence ≥ 0.90):**
   - New statement directly denies or reverses a prior active decision (e.g., "PostgreSQL for database" vs "Switching to MongoDB").
   - Action: Manager issues an **Alert Receipt** citing the exact prior statement and vector memory ID.
2. **Blocker Dependency (Confidence ≥ 0.85):**
   - New claim asserts that a subsystem or task is failing or stalling progress on a commitment.
   - Action: Target commitment state updates from `OPEN` to `BLOCKED`.
3. **Blocker Resolution (Confidence ≥ 0.85):**
   - New claim confirms a prior blocker is resolved (e.g., "Auth is fixed now").
   - Action: Prior claim moves to `RESOLVED`; blocked commitment returns to unblocked status.
4. **False Conflict / Hallucination Suppression:**
   - Statements with cosmetic topic overlap but unrelated scopes (e.g., discussing dinner vs discussing project deadlines) must be marked `unrelated` with `confidence < 0.50`. No alert permitted.

---

## 5. Grounding & Zero-Hallucination Mandate

1. **Cryptographic Vector Traceability:**
   - Any alert generated by the Manager Agent MUST cite a `target_id` that is confirmed present in the Qdrant retrieval result.
   - If an agent cites a memory ID not returned by Qdrant or references statements not in the retrieved payload, the **Hallucination Verification Guard** immediately drops the alert and registers a hallucination suppression event.
2. **Evidence Preservation:**
   - Receipts must present the verbatim original quotation (`evidence`) alongside the new statement (`statement`) to provide incontrovertible conversational proof.
